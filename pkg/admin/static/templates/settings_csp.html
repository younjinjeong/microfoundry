2. Create an IAM Role with the trust policy:

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Federated": "arn:aws:iam::ACCOUNT:oidc-provider/YOUR_KEYCLOAK"},
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": {
        "YOUR_KEYCLOAK:aud": "sts.amazonaws.com"
      }
    }
  }]
}

3. Attach the required permissions policies to the role (e.g., AmazonRDSFullAccess, AmazonElastiCacheFullAccess).

4. Enter the Role ARN above and click Test Connection to verify the token exchange.

GCP OIDC Setup Guide

1. Create a Workload Identity Pool in your GCP project:

gcloud iam workload-identity-pools create microfoundry-pool \
  --location="global" \
  --display-name="MicroFoundry Pool"

2. Add an OIDC provider to the pool:

gcloud iam workload-identity-pools providers create-oidc keycloak \
  --location="global" \
  --workload-identity-pool="microfoundry-pool" \
  --issuer-uri="{{if index $c "KeycloakIssuer"}}{{index $c "KeycloakIssuer"}}{{else}}https://keycloak.example.com/realms/microfoundry{{end}}" \
  --allowed-audiences="//iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/microfoundry-pool/providers/keycloak" \
  --attribute-mapping="google.subject=assertion.sub"

3. Grant the service account token creator role:

gcloud iam service-accounts add-iam-policy-binding SA_EMAIL \
  --role="roles/iam.workloadIdentityUser" \
  --member="principalSet://iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/microfoundry-pool/*"

4. Enter the provider resource name and SA email above, then click Test Connection.
